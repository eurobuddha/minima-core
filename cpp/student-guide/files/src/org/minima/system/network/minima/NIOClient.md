## What this file does

Maintain one connection’s metadata and incremental length-prefixed byte transport across nonblocking reads and writes.

## Follow the logic

1. The connecting constructor creates identity/host metadata and captures the manager but leaves buffers and queues uninitialized. The connected constructor also allocates two 8192-byte buffers, the temporary read array, outgoing queue and connection timestamps.
2. sendData holds the queue lock, checks key validity, appends the supplied data, enables read/write interest and wakes the selector. Failure after append leaves the queued item present.
3. handleRead first performs one channel read, rejects EOF, accounts the byte count and returns on zero. After flipping the buffer it reads a signed big-endian four-byte length only when all four bytes are available.
4. Reject lengths above 256 MiB; other invalid lengths fail later through allocation/copy rules. Accumulate payload across reads. At exact completion post NIO_NEWMSG with UID, current full address and payload, then clear the accumulation and update last-read time. A posting failure occurs before that cleanup.
5. handleWrite fills available space with queued frames, writing each four-byte length before its payload. Oversized queued data is removed and logged, then the fill loop stops. It writes the prepared buffer once, accounts bytes, removes write interest only when all buffered/current/queued data is gone, and compacts remaining bytes.
6. Metadata includes separate socket port and advertised Minima port; full address prefers the latter unless it is -1. disconnect cancels the key before closing the socket within one Exception catch, so cancel failure can skip close.

## How the translation is approached

The translation reuses FastByteArrayStream, NIOTraffic, Message and socket/key interfaces with explicit buffer position/limit state. Shared queued data and runtime receivers retain lifetimes; metadata and queue locks plus atomic tracing avoid native data races. POSIX transport and selector integration are separate layers; generic diagnostic text remains incomplete.

## What the tests tell us

[Read the differential experiment](../../../../../../../../tools/nio_client_differential.py). NIOClientOracle bypasses Main startup but executes the original client constructors/methods on controlled Channel/Key objects. Both harnesses compare full buffer hashes/positions, accumulated/current data, queue snapshots, traffic, posted messages, wake/interest/cancel effects and metadata after each operation. Cases split headers and payloads around 8192, throttle writes to zero/one byte, inject failures and test invalid/empty frames. Random UID format and clock effects are checked without equal entropy; errors are normalized. No test was rerun while authoring this lesson; this describes the experiment, not a new passing result.
