## What this file does

Validate an address format and report its wallet relevance flags.

## Follow the logic

1. Normalize the address through Command.getAddressParam.
2. If it starts with0x, require66 characters; then require a0x or Mx prefix.
3. Obtain the wallet, parse bytes and create both HEX and displayed Minima forms.
4. Return normalized original,0x,Mx,relevant and simple fields using wallet lookups.

## How the translation is approached

C++ invokes the required ChainServices address-relevance/simple callbacks after validation. Those callbacks are a runtime boundary, not a native persistent wallet implementation.

## What the tests tell us

The Java fixture injects tracked/simple address sets with known overlapping membership. Native callbacks implement the corresponding controlled sets. The driver checks those four combinations in HEX/Mx form, malformed lengths, invalid prefixes and missing input.

The actual [command driver](../../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../../build/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.
