## What this file does

Supply the shared parameter rules and JSON response envelope used by commands.

## Follow the logic

1. Store command/help text and an initially empty shared parameter object. Complete-command and MiniDapp ID metadata are independent fields.
2. getParam distinguishes a missing key from a present value. Present values must be strings, are trimmed and must not be blank. A default applies only when the key is absent; it does not repair a null or invalid present value.
3. Boolean access accepts only the exact trimmed string true. Number access delegates to MiniNumber. Data access converts Mx or HEX and wraps conversion failures as a CommandException. Address access has different source catch/normalization rules and permits some plain text to pass to its caller.
4. JSON object/array access returns the existing object reference, including null where the source cast permits it. Type predicates test the actual stored object type.
5. getJSONReply returns command, status=true and pending=false. It includes the actual parameter object only when nonempty, so later parameter mutation can remain visible through a prior reply.

## How the translation is approached

C++ uses an ordered shared JSONObject for parameters, optional strings/values for nullable defaults and explicit overloads for null defaults. Existing MiniNumber, Address and JSON code supply conversions. The narrow getParam accessor now delegates to the existing UTF-16 accessor, retaining its explicit NullPointerException and ClassCastException checks before encoding the result. Arbitrary unpaired-surrogate values and other overload boundaries still need review.

## What the tests tell us

The driver crosses absent/present keys with null, empty/blank strings, booleans, numbers, arrays, objects, Unicode, malformed Mx/HEX and numerical extremes. It tests null defaults separately. reply obtains a response then mutates parameters; alias obtains a nested object then changes it, directly checking shared-reference behavior.

The actual [command driver](../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../build/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.

## Newly observed parameter failures

The [wallet-command lab](../../../../../../new-tests/wallet-commands.md) supplies missing, blank, null and non-string parameters to six fields across actual commands. The first null case exposed bad_variant_access in the native narrow getter. Reusing getParamUTF16 corrects the exception category and retains the original default and trimming rules. The expanded 675-program corpus passes in both builds. Java-specific null/class-cast diagnostic expressions remain normalized.

The [witness-command lab](../../../../../../new-tests/witness-commands.md) exposed the same category issue in getJSONObjectParam: a Boolean produced bad_variant_access. The accessor now throws the existing JavaClassCastException for wrong nonnull types and preserves null/shared-object results. The expanded 418-program witness regression and all nine selected suites pass in both builds; the lab records the exact validation scope.

## Nullable replies and references

The no-argument runCommand API now uses the existing JSONValue because Java's JSONObject reference can be null. A concrete command still constructs its ordinary JSONObject reply, which is wrapped by the existing JSONValue constructor. String-taking helper overloads keep their object result type. This is a native representation change, not a rewrite of each command's algorithm. JSONValue can represent more kinds than Java's return type; production command bodies return objects or null, and the runner checks the object cast. See the [nullable-reply lab](../../../../../../new-tests/nullable-command-replies.md).
