## What this file does

Verify signed data with an explicitly supplied public key.

## Follow the logic

1. Read data, public key and serialized signature in that order through Command’s data conversion.
2. Decode Signature and obtain its root public key. Reject a mismatch with the supplied key before cryptographic verification.
3. Configure TreeKey with the signature root and verify the data.
4. For invalid cryptography, return status=false with a message; for valid cryptography, return response:"Signature valid". A key mismatch instead throws CommandException.

## How the translation is approached

C++ reuses Signature and TreeKey. It explicitly rejects a missing decoded signature, with that generic error normalized in this suite. The distinct mismatch/error/invalid-result channels remain significant.

## What the tests tell us

Java generates real signatures at key-use positions0,1 and3. The driver verifies them, then replaces/appends/truncates each of data/publickey/signature and adds missing/empty/malformed values.

The actual [command driver](../../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../../validation/checkpoint-360/normal/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.
