## What this file does

Distinguish a command-level error from a generic runtime failure.

## Follow the logic

1. Receive an error message and pass it unchanged to the superclass.
2. Let command/runner catch sites decide how to display it. This class itself performs no logging, retry or response construction.

## How the translation is approached

The native class derives from std::runtime_error and retains the supplied message, including an explicit null-message state and embedded NUL bytes. The complete stored string is retained separately from the null-terminated what() view. getMessage returns an optional string; the public runner preserves null as JSON null. The command harness catches it before std::exception and renders COMMAND_ERROR:<message>. Java’s checked-exception compilation rule has no direct C++ equivalent.

## What the tests tell us

Missing/blank required parameters, invalid conversion kinds and wrong signature public keys produce command-specific failures. The separate CommandException catch means a port that throws only generic errors will disagree even when both reject the request.

The actual [command driver](../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../build/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.

The [wallet-wrapper experiment](../../../../../../../tools/wallet_wrappers_differential.py) adds a child rejection with no error field and checks both direct exception category and public runner error:null without generic exception logging. The final group passes 659 programs and 2,060 child calls in normal and ASAN/UBSAN builds, including null, empty, Unicode and embedded-NUL messages.
