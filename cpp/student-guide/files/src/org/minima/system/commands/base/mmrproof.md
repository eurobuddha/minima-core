## What this file does

Reconstruct an MMR root from a supplied leaf and proof, then compare hash and sum.

## Follow the logic

1. First require the presence of root, proof and data together.
2. Read data and root, split optional colon sums and trim the split components; sums default to zero.
3. Build a typed leaf, decode the serialized proof and fold it with calculateProof.
4. Return the input, leaf, calculated final data and a Boolean equality against the expected root.

## How the translation is approached

C++ delegates leaf/proof operations to existing MMR classes and mirrors split/trim behavior. The command’s unused nested record remains represented in the header; it is not part of this execution path.

## What the tests tell us

Using actual mmrcreate results, the driver checks valid leaves/proofs and independently changes data, root sums and proof bytes; it adds truncation, trailing bytes, spaces and a root without an explicit sum. This distinguishes proof folding from mere parse success.

The actual [command driver](../../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../../validation/checkpoint-360/normal/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.
