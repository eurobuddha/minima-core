## What this file does

Generate random bytes, hash them and optionally derive a display key code.

## Follow the logic

1. Read size as MiniNumber with default32, convert it to a Java-style int and request that many random bytes. This happens before hash-type validation.
2. Select exact sha2/sha3 with default sha3 and hash the generated bytes.
3. Return the original size text, random HEX, digest and type. For an integer byte count at least16, Base32-encode the random bytes and take five four-character groups at source-defined offsets.

## How the translation is approached

C++ reuses OS-random MiniData and Crypto, with an explicit negative-array-size error. The key-code substring indices are preserved, including gaps between groups; a normal grouped Base32 formatter would not be equivalent.

## What the tests tell us

Deterministic failure/zero-size cases compare Java and C++ output. Nonempty random cases instead verify each runtime’s byte length, hash digest and exact Base32 substring construction. Fractional and wrapping size inputs distinguish displayed MiniNumber size from allocated int count.

The actual [command driver](../../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../../validation/checkpoint-360/normal/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.
