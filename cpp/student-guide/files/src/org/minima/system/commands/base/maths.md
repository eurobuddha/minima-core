## What this file does

Evaluate text using the actual KISS arithmetic and return the variable returnvalue.

## Follow the logic

1. Read calculate and the optional exact-string logs Boolean.
2. Construct the script LET returnvalue = followed by the supplied text, using a Contract with empty transaction/witness context and source-selected cleaning mode.
3. Run the Contract, then read returnvalue and call toString. The command does not first inspect parse/success flags.
4. Return the result and optionally the complete trace.

## How the translation is approached

C++ reuses Contract and the VM’s MiniNumber arithmetic. Its explicit missing-returnvalue check represents the Java dereference failure, with generic diagnostics normalized by this suite.

## What the tests tell us

The driver tests precedence, SIGDIG, strings/booleans/HEX, division by zero, negative square root, globals, malformed input and text containing an additional LET/RETURN. This demonstrates that the source constructs a script rather than using a separate calculator grammar.

The actual [command driver](../../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../../validation/checkpoint-360/normal/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.
