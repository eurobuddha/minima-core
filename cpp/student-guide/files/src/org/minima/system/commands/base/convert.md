## What this file does

Convert bytes between HEX, Minima address text, string encoding and Base64.

## Follow the logic

1. Read and lowercase from/to, then obtain data as stringified JSON or a string parameter. These operations occur before the conversion try block.
2. Decode the selected input format into one MiniData value. Reject an unknown FROM kind.
3. Encode those same bytes into the requested output format; reject an unknown TO kind.
4. Rethrow CommandException unchanged and wrap other caught conversion exceptions with their source-style text. Return response.conversion.

## How the translation is approached

C++ reuses MiniData, Address, MiniString and the existing Base64 helpers. Java-style case conversion is reused. Keeping decode and encode around a byte value avoids lossy text conversions for arbitrary binary input.

## What the tests tell us

The driver crosses formats and malformed values, enumerates short Base64 strings over an alphabet containing padding, invalid punctuation and non-ASCII text, and round-trips deterministic arbitrary bytes. It also tests missing parameters and case/space variations of kind names.

The actual [command driver](../../../../../../../../tools/command_differential.py) creates the inputs; [CommandOracle.java](../../../../../../../../support/CommandOracle.java) runs the pinned Java commands and [command.cpp](../../../../../../../../support/command.cpp) runs the native commands. The oracle uses a synthetic wallet address cache, not durable wallet storage. CommandException messages are compared separately, while other exceptions become ERROR. The existing [normal report](../../../../../../../../validation/checkpoint-360/normal/command-differential-results.json) records 12,289 cases passed, zero failures. This is a snapshot of the whole suite, not a new run or this command’s dedicated case count. Random outputs use per-runtime property checks rather than equality between independently generated bytes.
