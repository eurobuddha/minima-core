## Purpose

Yylex is a generated finite-state lexer. It groups characters into tokens before the parser decides how those tokens fit together. The source is generated by JFlex 1.4.2 and uses UTF-16 character positions.

## Follow the algorithm

1. The DFA maps each input character to a character class, uses state-row plus class to find a transition, and remembers the last accepting position. On a failed transition it returns to that accepted endpoint, implementing longest-token matching.
2. Whitespace actions consume input without returning a token. Braces, brackets, commas and colons return punctuation tokens. Number actions create Long or Double; range/conversion failures are separate from grammar errors.
3. An opening quote clears the string buffer and enters STRING_BEGIN. Ordinary runs append text; escapes append decoded characters, including one UTF-16 unit per Unicode escape. Closing quote returns the complete string and restores the initial lexical state.
4. The Java scanner refills a 16384-character buffer, compacts consumed input, grows when necessary, and handles a Reader returning zero by trying one character. yyreset discards old buffered state without closing the old reader; yyclose closes the active reader.
5. Unexpected characters raise ParseException at the current token start. EOF returns null. yytext/yylength expose the matched slice, and yypushback rewinds its marked endpoint; the Java bounds check rejects only counts greater than the matched length.

## How the C++ translation works

The native code reuses the extracted DFA tables and action mapping directly, operating on a complete UTF-16 string. Numeric actions use from_chars and strtod; string escapes and token classes retain the table behavior. Native input is prebuffered, yyclose has no Reader to close, and negative pushback is rejected although Java does not explicitly reject it. This is a lexical counterpart with incomplete scanner/IO API parity.

## Understanding the tests

The driver tests lexical mode for every corpus input, comparing every token’s start position, type and value plus final position. The corpus includes all ASCII characters in quoted text, raw controls, malformed/unpaired Unicode escapes, integer overflow, exponent underflow/overflow, numeric boundary values and random strings. DOM/event modes reuse the same lexer and compare error positions.

## Limits and a useful next test

The string-input corpus does not exercise refill boundary effects, zero-returning/failing Readers, close/reset ownership, custom lexical states or pushback. A useful future fixture should split an escape and a long number across the Java buffer boundary and inject an IO failure after partial text.
