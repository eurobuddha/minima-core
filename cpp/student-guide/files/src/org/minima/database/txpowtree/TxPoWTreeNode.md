## Node-state command comparison

calculateRelevantCoins clears its computed values, obtains all coins, then loops over relevant entries inside the coin loop. When there are no relevant entries, Java never reads a coin’s fields. The earlier native helper call read every coin even for an empty entry list, raising an extra null error after a malformed SQL decode. The native body now follows the source nested loop and first-match break. SQL still runs even for an empty relevant-entry list. Replaced-list alias identity remains a separate open issue. See [the lab](../../../../../../new-tests/node-state-commands.md) for the failing examples and final comparison evidence.

## What this file does

Combines one TxBlock with a branch-local MMR, coin/relevance caches, parent links and notification effects.

## Follow the logic

1. Build an MMR at the block’s height from previous peaks and calculate the next leaf number. For each input, deep-copy its coin, mark it spent and update its leaf with value zero through the supplied proof.
2. For each output, deep-copy it, assign the next MMR entry and creation block, mark unspent and append a leaf valued by its amount. The original output is used for relevance checking, so state removed from the stored copy can still matter.
3. With relevance enabled, store processed coins in RAM or CoinDB. A wallet address match or matching HEX state address/key marks an entry relevant. Emit NEWCOIN and configured-address notifications, restoring removed state into output notification JSON when available.
4. Finalize the MMR, recompute relevant coins by matching entry numbers and request a balance update if any relevant coin changed. Removing an entry from the relevance list does not immediately refresh the computed coin list.
5. Adding a child sets both its tree parent and MMR parent before appending it. getParent(N) clamps at the oldest ancestor and returns self for nonpositive N; getPastNode searches an exact height.
6. copyParentRelevantCoins materializes surviving relevant ancestor leaves into this MMR before detaching history. checkFullTxns memoizes successful existence checks forever; failed checks are retried later.
7. Wire order is TxBlock, MMR, all coins and relevant entry numbers. Reading resets children/weight/parent/relevant entries but does not clear the RAM coin list or full-check flag, so repeated in-place reads can accumulate coins.
8. Cascade notification emits block notice, stores the block’s on-chain record, emits transaction notices and records transaction IDs, then emits watched input/output coin notices. Ordering matters if a callback fails midway.

## How the translation is approached

C++ reuses applyBlockMMR and ChainServices callbacks for wallet/SQL/event effects. TxBlock and TxPoW have shared ownership, children own nodes and parent links are weak. Coin collections remain value vectors, which does not reproduce every Java collection/object alias. Standard error text and std::clog output are not fully equivalent to the Java logger.

## What the tests tell us

The [Java tree oracle](../../../../../../../support/TreeOracle.java), [native harness](../../../../../../../support/tree.cpp) and [driver](../../../../../../../tools/tree_differential.py) compare 450 seeded trees, unusual heights/weights, duplicate IDs, trims and print depths; a 513-node chain checks the 512-entry pulse cap. Another family builds block nodes, changes relevant-entry lists, writes/reads node bytes, appends trailing data and truncates selected positions. The inspected [report](../../../../../../../build/tree-differential-results.json) has 1,027/1,027 matching cases. The harness uses RAM coin mode and normalizes failures to ERROR; it does not certify SQL/wallet bindings or exact exception classes.

## Limits and traceability

The basic tree fixture covers node bytes/MMR and selected relevance-list operations, not every notification or persistence path. Java RAM getAllCoins exposes its mutable backing list; native returns a value copy. SQL services, in-place read aliases, full-check invalidation and exact logger/errors remain partial or require more specific fixture review.
